# Named SPA route table honesty

**Status:** in progress (slice 1 done).
**Type:** ad-hoc plan (`.planning/quick/`)
**Related ADR:** [0005 — Web routes](../../../docs/adrs/0005-web-routes.md) (**Proposed**, not Accepted). This plan makes production and unit tests match a stricter reading of the Decision at “SPA route convention” so that ADR can be tightened without lying. Agents do not set Status to Accepted.

## Goal

Stop duplicating SPA path shapes next to the named table. After this plan, in-app navigation is a named location, HTML `href` is compiled from that named location, and unit tests pin the helper or the route-table contract — not a second `/n42` dialect.

## Analysis (current vs ADR 0005:43–47)

The Proposed ADR says: one named table (path / name / props in metadata, pages wired separately); navigate by name and params, not concatenated path strings; helpers wrap hot destinations (note show); a path string is allowed only where an HTML `href` is required.

### Already honest

- Almost all Vue `:to` / `router.push` / `replace` sites already pass `{ name, params }` (or `noteShowLocation`).
- `WikiLinkToken.vue` uses `noteShowLocation` on `RouterLink`.
- Storybook and `all-stories.spec.ts` import `routeMetadata` without page components.
- `CircleShowPage` already compiles an href with `router.resolve({ name: "circleJoin", params }).href`.
- `routes.spec.ts` pushing `/n123`, `/n/888`, `/d/n/888` is the **URL-matching contract**. Path strings belong there.
- `pathnameLooksLikeInternalNoteShow` / `hrefLooksLikeConceptNotePath` classify **inbound** URLs (paste, markdown, retired shapes). That is not in-app navigation.
- `/d/:pathMatch(.*)*` concatenating the leftover path is inherent to “strip prefix and re-resolve”.
- Backend paths (`/login/continue`, `/api/…`) and concept-path hrefs (`/Folder/Title.md`) are not SPA screens.

### Dishonest today (this plan)

1. **`noteShowHref` concatenates `/n${noteId}`.** Compact path shape lives twice: `routeMetadata` (`/n:noteId(\\d+)`) and the helper. `CircleShowPage` already shows the honest compile. `noteShowHref` must not import `routes.ts` (that pulls pages and breaks Storybook).
2. **`/n/:noteId` redirect concatenates** `return \`/n${id}\`` instead of a named `noteShow` location.
3. **HTML-string wiki links navigate by path string.** `handleRichContentAnchorClick` does `navigateInApp(noteShowHref(id))` when `data-note-id` is present, else `router.push(href)`. `PropertyValueField` and `QuillEditor` both `router.push` that value. Token-wiki HTML from `replaceWikiLinksInHtml` and `propertyValueField` sets `href` via `noteShowHref` but **omits `data-note-id`**, so most `[[MyNote]]` clicks take the href-string branch. Path-markdown live anchors already set `data-note-id`. `wikiLinkAnchorHtml` already supports `noteId`.
4. **Unit tests pin `/n42` / `/n1` as if that were the navigation API.** Examples: `replaceWikiLinksInHtml.spec.ts`, `propertyValueField.spec.ts`, `NoteTextContent.wikiLinks.spec.ts`, `RichMarkdownEditor*.spec.ts`, `wikiLinkMarkup.spec.ts` (`expect(navigated).toBe("/n42")`), `QuillEditor.spec.ts` (`toHaveBeenCalledWith("/n1")`).
5. **Test-only routers invent a second path dialect.** `failureReportListTestSupport.ts` stubs `/failure-reports/:failureReportId` while production is `/failure-report-list/show/:failureReportId`. Named `:to` still works, so the stub never fails when the real path changes. `notebookPageTestSupport.ts`, `noteMoreOptionsDeleteTestSupport.ts`, and `SidebarFolderItem.spec.ts` copy path templates by hand.
6. **Settings names/paths are not in `routeMetadata`.** Nested `SettingsPage` lives only in `routes.ts`. Storybook’s metadata router has no settings screens. “One named table” is currently false for that tree.

### Honest, but do not over-stricten here

- Repeating `{ name: "notebookPage", params: { notebookId } }` is already named navigation. Helpers for every destination are optional later, not required for honesty.
- `typed-router.d.ts` is generated by `vue-router/vite` from page files (`/AdminDashboardPage`, …) and does **not** match the named table. It is unused at runtime (`@ts-nocheck`). Out of this plan.
- E2E `cy.visit('/recall')` etc. still hardcode paths. ADR already allows first-load visit of an href from the named table. **Out of this plan** (user asked production + unit tests). Follow-on: derive those hrefs from the same helper.
- `/users/identify` in `signInRedirectHref` is a full-page assign mixed with a backend continue URL. Separate work (STATE’s missing `010-sign-in-path-split`).

### Stricter ADR this plan enables (still Proposed)

After the slices, the Decision can honestly say:

- SPA path literals for screens live only in `routeMetadata` (plus the `/d/` leftover-path rewrite).
- In-app `push` / `replace` / `:to` is always a named location (or a helper that returns one).
- An HTML `href` is allowed only on rendered anchors, and is **compiled** from a named location against that table — never a second concatenated copy of the compact note-show path.
- Unit tests: navigation assertions use named locations; rendered-href assertions use `noteShowHref`; path strings only in `routes.spec.ts` (matching / redirects) and inbound URL classifiers.
- Test routers use production `routes` or stub records from `routeMetadata`, not a hand-copied path dialect.
- Nested layouts (notebook sidebar, settings) are assembled in `routes.ts` from named metadata entries.

Do **not** claim: no path strings anywhere; helpers for every `{ name: "notebooks" }`; `typed-router.d.ts` is the table; E2E never `visit`s an href.

**Human-owned:** tighten the Proposed ADR text in the last slice; do not rename to `*-accepted.md`.

## Key design decisions

- **Href compile, not concatenate.** `noteShowHref(id)` is `resolve(noteShowLocation(id)).href` on a metadata-only dummy router (same constraint as Storybook: no page imports). Production `routes.spec.ts` is the oracle: helper href equals `router.resolve(noteShowLocation(id)).href`.
- **`data-note-id` on every live wiki `<a>`.** Href stays for middle-click / copy. Click uses `noteShowLocation(id)`. Leftover in-app hrefs without a note id may still `push` a string (`RouteLocationRaw`).
- **Do not import `routes.ts` from `noteShowLocation.ts`.** That would pull pages into Storybook.
- **`quillHtmlToMarkdown` fixtures that feed `/n701` as inbound HTML** stay path strings: they test URL recognition, like `routes.spec.ts`.
- **No notebook/folder location helpers in this plan.**

## Slices

### 1. Compact note-show href is compiled from the named location — Structure `[x]`

`noteShowHref` resolves `noteShowLocation` on a metadata-only dummy router (`dummyRouteRecordsFromMetadata` in `noteShowLocation.ts`). Lockstep in `routes.spec.ts` vs production `router.resolve`. Storybook still has its own copy until slice 6.

**Learning:** `noteShowLocation.ts` now imports `routeMetadata`. Slice 2 must use `{ name: "noteShow", params }` in the redirect — do not import `noteShowLocation` into `routeMetadata` (cycle).

### 2. Legacy `/n/:noteId` redirect is a named location — Structure `[ ]`

In `routeMetadata`, redirect `/n/:noteId` with `{ name: "noteShow", params }` (not `noteShowLocation` — that module now imports this file). Do not concatenate `` `/n${id}` ``. Existing `routes.spec.ts` redirect tests stay the URL contract (they still `push("/n/888")`).

### 3. Live token wiki anchors include `data-note-id` — Structure `[ ]`

Pass `noteId` into `wikiLinkAnchorHtml` from `replaceWikiLinksInHtml` (both the `[[inner]]` replace and the unresolved-upgrade live element) and from `propertyValueField` live wiki HTML. Path-markdown anchors already have the attribute.

- Tests that snapshot token-wiki HTML must expect `data-note-id` (and may still use `/n42` until slice 5).
- No click-handler change yet.
- **Enables slice 4 only.**

### 4. Wiki in-app navigation pushes a named location — Structure `[ ]`

`handleRichContentAnchorClick` calls `navigateInApp(noteShowLocation(id))` when the live wiki has a note id. Callback type is `RouteLocationRaw`. `QuillEditor` / `PropertyValueField` `router.push` that value.

- Red first: `wikiLinkMarkup.spec.ts` expects `noteShowLocation(42)` not `"/n42"`; `QuillEditor.spec.ts` fixture includes `data-note-id` and expects `noteShowLocation(1)`.
- Leftover non-wiki in-app hrefs still `push` the href string.
- User URL is unchanged.

### 5. Wiki HTML unit tests pin `noteShowHref`, not `/n` literals — Structure `[ ]`

Replace rendered-href expectations with `noteShowHref(id)` in the wiki renderer tests: `replaceWikiLinksInHtml.spec.ts`, `propertyValueField.spec.ts`, `NoteTextContent.wikiLinks.spec.ts`, `RichMarkdownEditor.spec.ts`, `RichMarkdownEditor.propertyWikiLinks.spec.ts`. Leave `quillHtmlToMarkdown.spec.ts` inbound `/n701` fixtures as path strings.

- If the file list blows the time-box, commit the renderer specs first and finish editor specs in the same slice only if still green and small; otherwise split at Jidoka.

### 6. Test stub routers come from the named table — Structure `[ ]`

Extract the Storybook `routeMetadata` → dummy `RouteRecordRaw[]` mapping (preview + `all-stories.spec.ts`) into one helper. Switch hand-rolled test routers that duplicate SPA paths to that stub or to production `routes`:

- `failureReportListTestSupport.ts` (wrong path today)
- `notebookPageTestSupport.ts`
- `noteMoreOptionsDeleteTestSupport.ts`
- `SidebarFolderItem.spec.ts`

Named navigation in those tests must still resolve. Do not keep a second path dialect.

### 7. Settings names and paths live in `routeMetadata` — Structure `[ ]`

Add the settings tab records (paths `/settings`, `/settings/recent`, `/settings/access-tokens`, `/settings/recall-stats` and existing names) to `routeMetadata`. `routes.ts` still assembles the nested `SettingsPage` layout (same idea as `notebookSidebarNestedRouteNames`): skip those names in the generic map, read path/name from metadata.

- Settings unit tests that already `push({ name: "settingsRecent" })` stay named.
- Storybook metadata router can resolve settings names after this slice (dummy pages).
- **Jidoka:** if nested assembly exceeds the time-box, stop after metadata entries exist and the generic mapper does not double-register them; finish wiring rather than inventing a third table.

### 8. Tighten Proposed ADR 0005 (and the frontend test rule) — Structure `[ ]`

Update the SPA route-convention bullets in `docs/adrs/0005-web-routes.md` to the stricter honest wording in “Stricter ADR this plan enables”. Status stays **Proposed**. Add one line to `frontend-testing.mdc`: navigation assertions use named locations / `noteShowHref`; path strings only in route-table matching tests and inbound URL classifiers. `frontend.mdc` already says href via `noteShowHref`; leave it unless the wording now undersells “compiled from the named location”.
