## Spacing Scale

Declared values (must be multiples of 4). Align to Tailwind spacing already used on the recall page:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps between label fragments if needed |
| sm | 8px (`gap-2`) | Gap between potential-session rows; row internal padding-y |
| md | 16px (`px-4` / `gap-4`) | Horizontal inset of the potential-session strip under GlobalBar |
| lg | 24px | Not required for this strip (reserve for page sections elsewhere) |
| xl | 32px | Not required for this strip |
| 2xl | 48px | Not required for this strip |
| 3xl | 64px | Not required for this strip |

**Exceptions:** none for this phase. Do **not** introduce 44px touch-target chrome for display-only rows (Phase 5 may promote to controls).

**Layout placement (auto default — RESEARCH open Q1):** Render a **sibling strip below the ordinary progress bar**, still inside the recall `GlobalBar` content column (or immediately under `ProgressBar` within `RecallProgressBar`), so ordinary progress math / `#buttons` / cog remain untouched. Prefer a vertical stack: `[nav buttons][progress bar]` then `[potential learning session rows]`. Do **not** inject rows into the gray/blue progress fill.

**Focal point (recall top bar):** The ordinary progress bar (gray track / blue fill + finished/`toRepeatCount` title) remains the **primary visual anchor**. Potential-session rows are a **secondary** text strip beneath it — readable body copy, no accent, no button chrome — so they never compete with or visually merge into ordinary progress.

## Typography

Exactly four roles mapped to existing recall chrome (progress text is white on bar; session rows use theme content color):

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (`text-base`) | 400 | 1.5 | Potential-session row copy (primary readable text) |
| Label | 14px (`text-sm`) | 400 | 1.5 | Optional secondary meta (not required Phase 3; reserve) |
| Heading | 20px (`text-xl`) | 600 | 1.2 | Not used on this strip — do not add a section heading |
| Display | 28px | 600 | 1.2 | Not used this phase |

**Weights in use this phase:** 400 only on session rows. Do not bold the whole sentence; notebook title may use weight 600 **only** if needed for scanability — default is plain body 400 with title in the same sentence (matches E2E string).

**Auto default:** Single-line body copy at 16px / 400 / 1.5; wrap on narrow viewports (see UI Considerations).

## Color

Use DaisyUI semantic tokens (theme-safe light/dark). Do **not** invent a new accent palette for potential sessions.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-base-100)` | Page / bar surrounding surface |
| Secondary (30%) | Existing progress bar chrome (`gray` track / `blue` fill in `ProgressBar.vue`; diligent `#dc2626`) | Ordinary recall progress only — **unchanged** |
| Accent (10%) | `var(--color-primary)` / `daisy-btn-primary` | **Reserved — not used this phase** (Phase 5 commission CTA) |
| Destructive | `daisy-btn-error` / alert error | Not used this phase |
| Session row text | `var(--color-base-content)` | Potential-session copy |
| Session row surface | transparent or subtle `color-mix` of `base-content` at ≤8% on `base-100` | Optional strip background; prefer transparent to avoid new card chrome |

**Accent reserved for:** Phase 5 commission primary CTA only. Phase 3 display-only rows must **not** use `daisy-btn-primary`, `daisy-badge-primary`, or progress-fill blue as a “new work type” signal that could be confused with ordinary recall progress.

**Ordinary recall separation (D-05):** Progress finished/`toRepeatCount` text, bar fill ratio, and nav recall badge stay ordinary-only. Potential sessions never alter those colors or counts.

## Copywriting Contract

Glossary term: **potential learning session** (ADR 0001 §3). Match draft feature / E2E step wording exactly.

| Element | Copy |
|---------|------|
| Primary CTA | **None this phase** (D-04 display-only). Do not label rows “Commission” or open a dialog. |
| Populated row (canonical) | `{n} potential learning session to commission for notebook "{notebookName}"` — use **singular** “session” even when `n` is parameterized (draft feature / RESEARCH A3). Example: `1 potential learning session to commission for notebook "Spanish conversation"`. |
| Empty state heading | *(no dedicated empty UI)* — when `potentialLearningSessions.length === 0`, render **nothing** (no strip, no “0 potential…” unless E2E later requires the zero-count assertion on a specific notebook; default: omit rows). |
| Empty state body | N/A — silent absence |
| Error state | No new error chrome for this strip. Recalling load failures continue to use existing recall page / API error paths. Do not show a false “no potential sessions” empty if the recalling request failed. |
| Destructive confirmation | None — no destructive actions this phase |

**Multi-notebook:** One row per notebook (POT-02). Each row uses the same template with that notebook’s title.

**Nav / ordinary copy unchanged:** Sidebar / “notes to recall” badge copy stays ordinary-only (existing steps).

## UI Considerations

> Shape-rooted UI state coverage for the potential-learning-session list strip.

Applicable state considerations resolved: **7 covered, 1 backstop, 0 unresolved**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | potential-session list | ✅ covered | Zero sessions → render no rows / no strip (silent absence). Ordinary finished-recall alert unchanged. |
| loading | potential-session list | ✅ covered | No separate skeleton for this strip; rows appear when recalling payload is applied (same load path as progress bar). Do not flash empty then populate with a dedicated spinner on the strip. |
| error | potential-session list | ✅ covered | No strip-local error UI; rely on existing recalling failure handling. Never treat load failure as “zero potential sessions” without distinguishing failure. |
| populated | potential-session list | ✅ covered | One row per notebook with canonical glossary copy and notebook title from DTO. |
| partial | potential-session list | ✅ covered | Missing notebook name must not happen if API contract holds; if name empty, still show row with empty quoted title only if fixture forces it — prefer backend always sends `notebookName`. |
| overflow | potential-session list | ✅ covered | Many notebooks: stack rows vertically with `gap-2`; strip may grow; parent GlobalBar / page already scrolls horizontally for nav — vertical overflow wraps within recall page column without covering quiz content awkwardly (strip stays in top bar area). |
| zero-one-many | potential-session list | ✅ covered | Zero = hidden; one = single row; many = one row per notebook (POT-02). Copy keeps singular “session” per draft feature. |
| long-text | notebook title in row | 🧪 backstop | Long notebook titles wrap within the strip (`break-words` / normal wrap); no ellipsis truncation that would break E2E substring match on full title. Verify with held-out/visual or unit fixture using a long title. |

**Security / XSS:** Interpolate `notebookName` as text only (Vue mustache). Never `v-html` notebook names (RESEARCH Security Domain).
