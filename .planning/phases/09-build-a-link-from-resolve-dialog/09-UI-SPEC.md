# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** From a resolve-dialog match row, user can **Build a link** via the existing property/relationship offer as a **single Modal step** (not nested PopButton), remain on the accidental-match result, and see the CTA hidden when the reviewed notebook is readonly or required realms are unloaded. Requirements AMR-06, AMR-07.

**Inheritance:** Spacing scale, shell typography/color, Resolve CTA chrome, Modal dismiss, Phase 8 row title/path layout, and Phase 7–8 testids are unchanged unless this contract names a delta. Sources: `08-UI-SPEC.md`, `07-UI-SPEC.md`, CONTEXT D-01..D-09, RESEARCH.

## Interaction Contract

### Layout order (result chrome) — unchanged from Phase 7/8

1. Outcome alert (`accidental-match-alert` when applicable)
2. Resolve `PopButton` (**only if** `outcome === "ACCIDENTAL_MATCH"` **and** `matchedNotes.length > 0`)
3. `NoteUnderQuestion` → `ViewMemoryTrackerLink` → reviewed `NoteShow`
4. OVERLAP try-again branch unchanged

**Forbidden on result:** `matched-notes-section`, matched `NoteShow`s, per-match link `PopButton`s on the result surface.

### Single-Modal step swap (AMR-06 / D-01..D-05) — locked

- **One** Modal only — the existing Resolve `PopButton` Modal (`showModal`).
- **Never** wrap `MatchedNoteLinkOffer` in a nested `PopButton` / second `Modal`.
- Host step state in resolve Modal content (`AccidentalMatchResolveDialog` preferred):

```typescript
type ResolveStep =
  | { kind: "list" }
  | { kind: "link"; matchedNoteId: number }
```

| Step | Body |
|------|------|
| `list` | Match rows (Phase 8 title + path) + gated **Build a link** per row |
| `link` | `MatchedNoteLinkOffer` with `reviewedNoteId` + that row’s `matchedNoteId` |

- Pass `reviewedNoteId` from answered recalled note into the dialog host (`AnsweredSpellingQuestion` stays CTA + `PopButton` only).
- Reuse `MatchedNoteLinkOffer` as-is (`navigate-on-success=false`; property/relationship pipeline unchanged).
- Map offer `@closeDialog` (go-back, property success, relationship success) → **return to list step** inside the same Modal.
- Do **not** wire offer `closeDialog` to PopButton `closer`.
- User dismisses the resolve dialog only via existing Modal closer (X / backdrop / ESC / route change).
- After successful link: user remains on accidental-match **result** chrome; resolve Modal stays open on the **list** step (D-04).
- Rely solely on offer’s existing go-back (Reply) for returning from offer → list; **no** duplicate host “Back” chrome (discretion default).

### Per-row Build a link (D-03)

- Place **Build a link** at the bottom of the row stack (after title and optional path), still inside `resolve-match-row-{id}`.
- Visual density (discretion): `daisy-btn daisy-btn-secondary daisy-btn-sm` — matches Resolve CTA size/weight.
- Click → set step to `link(matchedNoteId)`; do not navigate away; do not open a second dialog.
- Do **not** add **Add as overlapped note** this phase.

### Readonly / unload gates (AMR-07 / D-06..D-07)

Hide **Build a link** (prefer omit, not disabled-looking) when any of:
1. No `currentUser` (port v1.1 gate)
2. Reviewed realm not yet loaded
3. `reviewedRealm.notebookRealm.readonly === true`
4. Matched realm for that row not yet loaded

Still show when gate fails:
- Match title (clickable) and path when topology/realm available (Phase 8 unchanged)

Hydrate:
- Reviewed realm once at dialog host (prefer host-level; avoid N× duplicate reviewed loads).
- Match realms continue per-row via existing `getNoteRealmRefAndLoadWhenNeeded` (Phase 8).
- No new capability API / OpenAPI change for gating.

### Dismiss (AMR-03) — unchanged

Overlay X, backdrop, ESC via `modalStack`, route change close — leave user on result when dismissing without navigating away. Offer step does not add a second dismiss path beyond Modal closer + offer go-back→list.

Offer step: reuse existing offer selectors (`Link to:`, `go-back-button`, property/relationship buttons) — no new offer testids required this phase.

### CTA visual specs

```
# Outer (unchanged)
PopButton
  title / aria-label: "Resolve accidental match"
  btn-class: "daisy-btn daisy-btn-secondary daisy-btn-sm mt-2"
  data-testid: "resolve-accidental-match"
  showCloseButton: true (default)

# Per-row (Phase 9 delta)
<button
  v-if="canBuildLink"
  type="button"
  class="daisy-btn daisy-btn-secondary daisy-btn-sm"
  :data-testid="`link-to-matched-note-${matched.id}`"
  title="Build a link"
  aria-label="Build a link"
>
  Build a link
</button>
```

### Row visual spec (Phase 9 delta on Phase 8 stack)

```
<li data-testid="resolve-match-row-{id}" class="flex flex-col gap-2">
  <NoteTitleWithLink :note-topology="matched" />
  <div v-if="realm" data-testid="resolve-match-path-{id}">
    <BreadcrumbWithCircle … />
  </div>
  <button v-if="canBuildLink" … data-testid="link-to-matched-note-{id}">
    Build a link
  </button>
</li>
```

### Offer host sketch

```
<!-- same Modal body; never nested PopButton -->
<ul v-if="step.kind === 'list'" data-testid="accidental-match-resolve-dialog">…rows…</ul>
<MatchedNoteLinkOffer
  v-else
  :reviewed-note-id="reviewedNoteId"
  :matched-note-id="step.matchedNoteId"
  @close-dialog="returnToList"
/>
```

## Accessibility (phase minimum)

| Requirement | Contract |
|-------------|----------|
| Resolve CTA name | Accessible name = visible label **Resolve accidental match** |
| Build a link name | Accessible name = visible label **Build a link** (`title` + `aria-label` match face text) |

| Focus | Rely on existing Modal `showModal` + autofocus; step swap stays inside the same `<dialog>` — do not invent a second focus trap |
| Dismiss | ESC / X / backdrop remain available on the outer Modal while on list **or** offer step |
| Offer go-back | Existing Reply control returns to list (not Modal dismiss) |
| XSS | Text interpolation only for titles / breadcrumb — never `v-html` |
| Nested dialog | Forbidden — prevents dual `showModal` focus/close fights |
