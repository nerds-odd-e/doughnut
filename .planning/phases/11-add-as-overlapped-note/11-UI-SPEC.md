# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase goal:** From a resolve-dialog match row, user can **Add as overlapped note**, which declares an overlap wiki-link alias on the **reviewed** note toward that match. After success, remain on the accidental-match result (no try-again, no SRS credit reclaim). Requirements AMR-08, AMR-09. AMR-07 hide gates reuse Phase 9.

**Inheritance:** Spacing scale, shell typography/color, Resolve CTA chrome, Modal dismiss, Phase 8 row title/path layout, Phase 9 **Build a link** single-Modal step + gates, and Phase 7–9 testids are unchanged unless this contract names a delta. Sources: `09-UI-SPEC.md` (primary visual inherit), `07-UI-SPEC.md` / `08-UI-SPEC.md`, Phase 10 util (no UI), CONTEXT D-01..D-11, RESEARCH.

**Phase 10 note:** `10-UI-SPEC.md` is N/A (Structure util only) — no visual tokens to inherit; this phase owns the CTA.

## Color

Use DaisyUI semantic theme tokens — no new hex palette. **Same 60/30/10 shell as Phase 7–9**, with accent reservation extended for the new per-row CTA:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-base-100)` | Recall result surface behind alert / reviewed note |
| Secondary (30%) | `var(--color-base-200)` | Modal panel (`bg-base-200` on existing Modal) |
| Accent (10%) | DaisyUI `secondary` button tokens via `daisy-btn-secondary` | Resolve CTA, **Build a link**, and **Add as overlapped note** |
| Destructive | DaisyUI `error` via `daisy-alert-error` | Accidental-match alert surface only (existing; not a button) |
| Content | `var(--color-base-content)` | Alert text, match titles, breadcrumb |

Accent reserved for:
1. **Resolve accidental match** CTA (`daisy-btn daisy-btn-secondary daisy-btn-sm`)
2. **Build a link** per-row CTA (`daisy-btn daisy-btn-secondary daisy-btn-sm`)
3. **Add as overlapped note** per-row CTA (`daisy-btn daisy-btn-secondary daisy-btn-sm`)

**Discretion default (locked here):** Both mutating per-row CTAs use **secondary** (not ghost) so peer actions share density and accent with Resolve / Build a link. Do **not** restyle Build a link to ghost to “make room” for overlap.

Not accent in this phase (leave as-is / do not redesign):
- Match title links (`NoteTitleWithLink` — content color)
- Path breadcrumb segments
- OVERLAP **Try again** (pre-existing sibling — must stay exclusive to graded `OVERLAP`)
- Modal close (ghost / icon-only)
- Offer-step choice buttons inside `LinkInsertionChoice` / `AddRelationshipFinalize` — inherited offer chrome

Alert mapping (unchanged):
- `ACCIDENTAL_MATCH` → `daisy-alert daisy-alert-error` + `data-testid="accidental-match-alert"`
- `OVERLAP` → `daisy-alert-warning` (no Resolve CTA; try-again exclusive to this outcome)

## Interaction Contract

### Layout order (result chrome) — unchanged from Phase 7–9

1. Outcome alert (`accidental-match-alert` when applicable)
2. Resolve `PopButton` (**only if** `outcome === "ACCIDENTAL_MATCH"` **and** `matchedNotes.length > 0`)
3. `NoteUnderQuestion` → `ViewMemoryTrackerLink` → reviewed `NoteShow`
4. OVERLAP try-again branch unchanged — **never** shown after dialog declare

**Forbidden on result:** `matched-notes-section`, matched `NoteShow`s, per-match mutating CTAs on the result surface outside the Modal.

### Per-row Add as overlapped note (AMR-08 / D-01..D-05) — locked

- Place **Add as overlapped note** in the same CTA row as **Build a link** (after title and optional path), still inside `resolve-match-row-{id}`.
- Layout: `flex flex-wrap gap-2` peer row — **Build a link** then **Add as overlapped note** (order locked: Build a link first).
- Visual density: `daisy-btn daisy-btn-secondary daisy-btn-sm` — same classes as Build a link / Resolve.
- Click → emit to dialog host; host runs `appendOverlapWikiLinkToNoteContent` → conditional `updateTextField(reviewedNoteId, "edit content", …)`.
- Do **not** introduce a nested Modal / PopButton for declare (D-01).
- Do **not** swap to the Phase 9 `link` offer step for this action — declare stays on the **list** step (unlike Build a link).
- After successful declare: remain on accidental-match **result** chrome; resolve Modal stays open on the **list** step (D-04). Do **not** force-dismiss.
- If util returns `null`: do **not** call `updateTextField`; stay on list with **no** outcome/UI flip and **no** new copy (D-05).

### AMR-09 — no try-again / no SRS reclaim (D-06..D-07)

- Content mutation only. Do **not** emit `retry`, re-submit the spelling answer, change `answer.outcome`, or offer credit reclaim / schedule undo for this answer.
- After declare: accidental-match alert still present; **no** `overlap-try-again` / `overlap-try-again-alert`.
- OVERLAP try-again remains exclusive to graded `outcome === "OVERLAP"`.

### Readonly / unload gates (AMR-07 / D-08..D-09) — reuse Phase 9

Hide **Add as overlapped note** under the **same** conditions as **Build a link** (prefer omit, not disabled-looking) when any of:
1. No `currentUser`
2. Reviewed realm not yet loaded
3. `reviewedRealm.notebookRealm.readonly === true`
4. Matched realm for that row not yet loaded

Prefer one shared gate helper (e.g. generalize `canOfferBuildLink` → mutating-action gate) so both CTAs stay in lockstep (D-09).

Still show when gate fails:
- Match title (clickable) and path when topology/realm available (Phase 8 unchanged)

Hydrate:
- Reviewed realm once at dialog host (prefer host-level).
- Match realms continue per-row via existing `getNoteRealmRefAndLoadWhenNeeded`.
- No new capability API / OpenAPI change for gating.

### Host ownership (D-03)

- Mutate handler lives in `AccidentalMatchResolveDialog` (or thin sibling under `recall/`), not by branching `AnsweredSpellingQuestion` outcome chrome.
- Keep ACCIDENTAL_MATCH vs OVERLAP templates outcome-discriminated (Pitfall 8).

### Dismiss (AMR-03) — unchanged

Overlay X, backdrop, ESC via `modalStack`, route change close — leave user on result when dismissing without navigating away.
